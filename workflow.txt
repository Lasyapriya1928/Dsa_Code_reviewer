🔹 STEP-1[Feature extraction]
What is an AST (Abstract Syntax Tree)?
An Abstract Syntax Tree (AST) is a tree representation of the structure of source code written in a programming language.
It shows how the code is organized syntactically (i.e., according to the grammar of the language), but without unnecessary details like brackets, semicolons, or commas.
Simple Example
Code:
a = b + 2
AST (conceptually) looks like:
     =
   /   \
  a     +
       / \
      b   2
Here:
= is the root node (assignment)
+ is a child node (addition)
a, b, 2 are leaf nodes (variables/values)
Why is AST important?
ASTs are used in:
Compilers & Interpreters (to understand and execute code)
Code analysis tools (like linters: ESLint, Pylint)
Code formatters (like Prettier, Black)
Static analysis & refactoring tools
AI code tools (like code completion, bug detection)

def __init__(self):
    self.num_loops = 0

    self.max_loop_depth = 0

    self.function_names = set()
    self.function_calls = []

    self.uses_list = 0
    self.uses_dict = 0
    self.uses_set = 0

    self.num_functions = 0

These are variables to store extracted features:
Variable	Meaning
num_loops	Total number of loops
current_loop_depth	How deep we are currently inside nested loops
max_loop_depth	Maximum nesting of loops
function_names	Names of all functions defined
function_calls	Names of functions that are called
uses_list	Whether a list is used (0/1)
uses_dict	Whether a dictionary is used (0/1)
uses_set	Whether a set is used (0/1)
num_functions	Number of functions in the code
🔹 Part 2 — Loop Detection
For loops
def visit_For(self, node):
    self.num_loops += 1
    self.current_loop_depth += 1
    self.max_loop_depth = max(self.max_loop_depth, self.current_loop_depth)

    self.generic_visit(node)
    self.current_loop_depth -= 1


What happens when a for loop is found in AST?
Increase total loop count
Increase current depth
Update max depth if needed
Visit everything inside the loop (generic_visit)
After finishing, decrease depth

Same for while loop:
def visit_While(self, node):
    self.num_loops += 1
    self.current_loop_depth += 1
    self.max_loop_depth = max(self.max_loop_depth, self.current_loop_depth)

    self.generic_visit(node)
    self.current_loop_depth -= 1

🔹 Part 3 — Function + Recursion Detection
When a function is defined:
def visit_FunctionDef(self, node):
    self.num_functions += 1
    self.function_names.add(node.name)
    self.generic_visit(node)

Example:
If code has:
def two_sum(nums):
Then:
num_functions = 1
function_names = {"two_sum"}
When a function is called:
def visit_Call(self, node):
    if isinstance(node.func, ast.Name):
        self.function_calls.append(node.func.id)
    self.generic_visit(node)

If the code calls:
two_sum(arr)
Then:
function_calls = ["two_sum"]

Checking recursion:
self.has_recursion = int(
    any(fn in self.function_calls for fn in self.function_names))


If a function calls itself, then:
has_recursion = 1
Else 0

🔹 Part 4 — Data Structure Detection
If the code contains:
A list → visit_List sets uses_list = 1

A set → visit_Set sets uses_set = 1

Example:

🔹 Complexity Rules (Carefully Chosen)
⚠️ These are heuristics, not mathematical proofs.
That’s okay — and you should say that in interviews.
Rule Set
Condition	              Estimated Complexity	                  Reason
No loops, no recursion	           O(1)	                      Constant work
Single loop, depth = 1	           O(n)	                      Linear iteration
Nested loops, depth = 2	           O(n²)	                  Quadratic
Nested loops, depth ≥ 3	           O(n³) or higher	         Polynomial growth
Recursion only	                   O(n) or O(2ⁿ)	         Depends on calls
Loop + recursion	               O(n log n) (heuristic)	 Divide & conquer

# in complexity_rules.py file the code gives us estimation of time complexity in the rule based approach mentioned above

🔹 Space Complexity Rules (Simple & Defensible)
Detected Feature	          Space Complexity	                 Explanation
No new DS, no recursion	            O(1)	                  Constant extra space
Uses list/dict/set	                O(n)	               Linear auxiliary storage
Multiple DS allocations             O(n)	                     Still linear
Recursion present	                O(n)	                       Call stack
Recursion + DS	                    O(n)	                   Dominated by linear
“Space complexity is estimated using heuristic rules based on auxiliary data structures and recursion. 
Since Python abstracts memory allocation, the system reports explainable approximations rather than exact usage.”
